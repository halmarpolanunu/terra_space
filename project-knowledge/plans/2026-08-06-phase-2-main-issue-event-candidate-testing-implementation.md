# Phase 2 Main-Issue and Event-Candidate Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a manually triggered n8n reliability-test workflow that reads one Phase 1 article, uses `google/gemma-4-12b-qat` to ground its main issue before detecting event candidates, and replaces that article's isolated Supabase test result.

**Architecture:** Keep Phase 1 news unchanged in `terra_space_news_v2`. Add one separate test row per source article in `terra_space_event_candidates_test`, keyed by `p1_news_uuid`. The inactive n8n workflow `Terra Space - Event` (`pO6m1mpaHz2Ae5ZR`) becomes a two-call, whole-document pipeline: issue detection and validation first, event detection and validation second, then create-or-update the single test row.

**Tech Stack:** n8n Form Trigger, Code, HTTP Request, If, and Supabase nodes; local LM Studio OpenAI-compatible endpoint; local Supabase/PostgreSQL with JSONB.

## Global Constraints

- Use only `google/gemma-4-12b-qat` for both model calls.
- Use the whole `p1_clean_content_text`; do not introduce chunking in this testing build.
- The user enters one existing `p1_uuid` into the n8n form for each run.
- Do not edit, delete, or add columns to `terra_space_news_v2`.
- Every saved main issue and candidate must have an evidence quote found verbatim in `p1_clean_content_text`; n8n, not Gemma, computes character offsets.
- Keep exactly one test row per `p1_news_uuid`; a later run replaces it.
- Use Jakarta/WIB-aware `timestamptz` values supplied by PostgreSQL or ISO-8601 timestamps from n8n.
- Before the SQL in Task 1 is applied, state exactly that it will create one empty test table, one uniqueness rule, one foreign-key relationship, and data-validation rules; obtain explicit user confirmation in chat. Do not run the SQL without that confirmation.
- Keep all durable documentation under `project-knowledge/` and run `tools/Validate-ProjectKnowledge.ps1` after documentation changes.

### Task 1: Create the isolated Supabase test table

**Files:**
- Modify: Supabase database schema only, through the owner-approved local Supabase migration/SQL workflow.
- Verify: `public.terra_space_event_candidates_test` and its constraints in the local Supabase database.

**Interfaces:**
- Consumes: `public.terra_space_news_v2(p1_uuid)` from Phase 1.
- Produces: one row per `p1_news_uuid`, used by n8n's Create and Update Supabase nodes.

- [ ] **Step 1: Request the required destructive-operation safety confirmation.**

Tell the owner: “This will create the new empty table `public.terra_space_event_candidates_test`. It will add a foreign-key link to existing Phase 1 article UUIDs, a unique rule that permits only one result per article, and JSON/status checks. It will not delete, update, or alter any existing Phase 1 news records. May I apply it?”

- [ ] **Step 2: Apply this SQL only after the owner explicitly confirms.**

```sql
create table public.terra_space_event_candidates_test (
  id bigint generated by default as identity primary key,
  p1_news_uuid uuid not null unique
    references public.terra_space_news_v2 (p1_uuid)
    on delete restrict,
  main_issue_status text not null
    check (main_issue_status in ('MAIN_ISSUE_FOUND', 'NO_MAIN_ISSUE', 'FAILED')),
  main_issue jsonb,
  event_detection_status text not null
    check (event_detection_status in (
      'EVENT_CANDIDATES_FOUND',
      'NO_EVENT_CANDIDATE',
      'NOT_RUN',
      'FAILED'
    )),
  event_candidates jsonb not null default '[]'::jsonb
    check (jsonb_typeof(event_candidates) = 'array'),
  model_name text not null,
  prompt_version text not null,
  main_issue_raw_output text,
  event_detection_raw_output text,
  error_message text,
  processed_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  check (
    (main_issue_status = 'MAIN_ISSUE_FOUND' and main_issue is not null)
    or (main_issue_status in ('NO_MAIN_ISSUE', 'FAILED'))
  ),
  check (
    (event_detection_status = 'EVENT_CANDIDATES_FOUND'
      and jsonb_array_length(event_candidates) > 0)
    or (event_detection_status in ('NO_EVENT_CANDIDATE', 'NOT_RUN', 'FAILED'))
  )
);
```

- [ ] **Step 1: Add `Build Main-Issue Request`, an n8n Code node.**

Build the request body exactly as below. The prompt asks Gemma for one central issue, permits an explicit no-issue result, and never asks it to calculate offsets.

```javascript
const system = [
  'You identify the single main issue of a news article for Terra Space.',
  'Use only facts explicitly stated in the article.',
  'Return JSON only, with no markdown or commentary.',
  'If the article has a meaningful central issue, return:',
  '{"status":"MAIN_ISSUE_FOUND","main_issue":{"label":"short label","summary":"one sentence","evidence_quote":"exact verbatim quote"}}',
  'If it has no usable main issue, return:',
  '{"status":"NO_MAIN_ISSUE","main_issue":null}',
  'Copy evidence_quote exactly from the article. Do not calculate character positions.',
].join('\n');

return [{
  json: {
    ...$json,
    main_issue_request: {
      model: $json.model_name,
      temperature: 0.1,
      max_tokens: 1024,
      reasoning_effort: 'none',
      messages: [
        { role: 'system', content: system },
        { role: 'user', content: `Title: ${$json.source_title}\n\nArticle:\n${$json.source_text}` },
      ],
    },
  },
```

- [ ] **Step 3: Add `Validate Main Issue`, an n8n Code node.**

```javascript
const base = $('Build Main-Issue Request').item.json;
const response = $json;
const raw = response?.choices?.[0]?.message?.content ?? '';

function failure(message) {
  return [{ json: {
    ...base,
    main_issue_status: 'FAILED',
    main_issue: null,
    main_issue_raw_output: raw || null,
    event_detection_status: 'NOT_RUN',
    event_candidates: [],
    event_detection_raw_output: null,
    error_message: message,
  }}];
}

if (!raw) return failure('LM Studio returned no main-issue content.');

let parsed;
try { parsed = JSON.parse(raw); }
catch { return failure('Main-issue response was not valid JSON.'); }

if (parsed.status === 'NO_MAIN_ISSUE') {
  return [{ json: {
    ...base,
    main_issue_status: 'NO_MAIN_ISSUE',
    main_issue: null,
    main_issue_raw_output: raw,
    event_detection_status: 'NOT_RUN',
    event_candidates: [],
    event_detection_raw_output: null,
    error_message: null,
  }}];
}

const issue = parsed.main_issue;
const quote = typeof issue?.evidence_quote === 'string' ? issue.evidence_quote : '';
const start = quote ? base.source_text.indexOf(quote) : -1;

if (parsed.status !== 'MAIN_ISSUE_FOUND' || !issue?.label || !issue?.summary || start < 0) {
  return failure('Main issue was missing required fields or its evidence quote was not found verbatim.');
}

return [{ json: {
  ...base,
  main_issue_status: 'MAIN_ISSUE_FOUND',
  main_issue: {
    label: issue.label,
    summary: issue.summary,
    evidence_quote: quote,
    evidence_start: start,
    evidence_end: start + quote.length,
    quote_grounded: true,
  },
  main_issue_raw_output: raw,
}}];
```

- [ ] **Step 3: Add `Validate Event Candidates`, an n8n Code node.**

```javascript
const base = $('Build Event-Candidate Request').item.json;
const response = $json;
const raw = response?.choices?.[0]?.message?.content ?? '';

function result(status, candidates, errorMessage = null) {
  return [{ json: {
    ...base,
    event_detection_status: status,
    event_candidates: candidates,
    event_detection_raw_output: raw || null,
    error_message: errorMessage,
  }}];
}

if (!raw) return result('FAILED', [], 'LM Studio returned no event-candidate content.');

let parsed;
try { parsed = JSON.parse(raw); }
catch { return result('FAILED', [], 'Event-candidate response was not valid JSON.'); }

if (parsed.status === 'NO_EVENT_CANDIDATE') {
  return result('NO_EVENT_CANDIDATE', []);
}

if (parsed.status !== 'EVENT_CANDIDATES_FOUND' || !Array.isArray(parsed.candidates)) {
  return result('FAILED', [], 'Event-candidate response had an unsupported status or candidate structure.');
}

const valid = [];
const rejected = [];
for (const candidate of parsed.candidates) {
  const quote = typeof candidate?.evidence_quote === 'string' ? candidate.evidence_quote : '';
  const start = quote ? base.source_text.indexOf(quote) : -1;
  const typeIsValid = ['RELATIONAL_INTERACTION', 'ENTITY_CENTRED_CHANGE'].includes(candidate?.classification);
  const entitiesAreValid = Array.isArray(candidate?.entities) && candidate.entities.every((value) => typeof value === 'string');

  if (candidate?.working_title && candidate?.phenomenon && typeIsValid && entitiesAreValid && start >= 0) {
    valid.push({
      working_title: candidate.working_title,
      classification: candidate.classification,
      phenomenon: candidate.phenomenon,
      entities: candidate.entities,
      evidence_quote: quote,
      evidence_start: start,
      evidence_end: start + quote.length,
      quote_grounded: true,
    });
  } else {
    rejected.push(candidate?.working_title || 'unnamed candidate');
  }
}

if (valid.length === 0) {
  const message = rejected.length
    ? `No candidate survived grounding and schema checks: ${rejected.join(', ')}.`
    : null;
  return result('NO_EVENT_CANDIDATE', [], message);
}

const message = rejected.length
  ? `Discarded ungrounded or incomplete candidates: ${rejected.join(', ')}.`
  : null;
return result('EVENT_CANDIDATES_FOUND', valid, message);
```
